# powerk

تحكّم في مشترك **LG U+ / Jinheung MTTL-W01** ذي المخارج الأربعة من المتصفح أو تطبيق
أندرويد، عبر خادمك بدلًا من سحابة الشركة المصنّعة.

[English](README.md) | **العربية**

| المكوّن | التنفيذ |
|---|---|
| الخادم | `server/`: حزمة FastAPI، اتصال TCP بالمشترك، القواعد، سجل الطاقة والحسابات |
| الواجهات | واجهة ويب و`android/` باستخدام Kotlin وJetpack Compose |
| أداة التهيئة | `tools/provision.py`: سكربت مستقل بمكتبة Python القياسية، يُنزّل من `/powerk.py` |
| اتصال المشترك | بروتوكول `up:...` غير مشفّر إلى عنوان IPv4 للخادم، على TCP **10086** |

## كيف يعمل

```text
phone / browser -- HTTPS --> Cloudflare -- HTTPS --> Caddy --> powerk
                                                               ^
                                                               | TCP 10086
                                                             strip
```

تحفظ التهيئة **عنوان IP لخادمك** داخل المشترك. يبدأ المشترك الاتصال من المنزل؛ لا تحتاج
إلى فتح منفذ على راوتر المنزل أو تغيير DNS أو تفليش الفيرموير. لا يمر اتصال المشترك عبر
Cloudflare. يمر الويب في نشر الإنتاج عبر Cloudflare وCaddy باستخدام HTTPS، بينما يمكن
لبيئة التطوير الاتصال مباشرة عبر HTTP على الشبكة المحلية.

ينفّذ الخادم القواعد حتى والهاتف مغلق. يرى كل حساب مشترَكاته المملوكة أو المشاركة معه فقط.
تستخدم واجهة الويب `/api/ws` للتحديثات اللحظية، وتعود إلى الاستعلام كل ثانيتين عند انقطاعه.
تبقى أوامر التحكم عبر HTTP. تطبيق أندرويد يعمل بنفس الطريقة، ويستقبل الإشعارات عبر FCM.

## المتطلبات

- مشترك MTTL-W01 وشبكة واي فاي 2.4 غيغاهرتز؛ إصدار الفيرموير المسجّل هو `0.1.54-1.0.66`.
- خادم يظل قيد التشغيل بعنوان IPv4 ثابت يستطيع المشترك الوصول إليه.
- Docker Compose للنشر المرفق، أو Python **3.11+** لتشغيل الخادم مباشرة.
- Python **3.8+** على جهاز به واي فاي للتهيئة؛ الخادم نفسه يمكنه استخدام Ethernet.
- متصفح أو هاتف أندرويد **8.0+**.

## الاستضافة الذاتية باستخدام Docker

إعداد النشر المرفق موجّه إلى VPS يعمل بنظام Ubuntu وعنوان الإنتاج المذكور أعلاه.
عدّل الدومين وIP والشهادات وأي قائمة MAC مسموح بها حسب خادمك، باتباع
[دليل التشغيل](deploy/README.md). أكمل خطوات Cloudflare وشهادة Origin CA وميزة
Authenticated Origin Pulls والجدار الناري **قبل تشغيل الخدمات**.

1. جهّز ملف الإعدادات من مجلد المشروع:

   ```sh
   cd deploy
   cp .env.example .env
   chmod 600 .env
   ```

2. عدّل `.env`: ضع اسم النطاق في `POWERK_DOMAIN`، وIPv4 الخادم في `POWERK_IP`، وMAC مشتركك في `POWERK_MAC` أو اتركه
   فارغًا. لتشغيل الحسابات فقط، اترك `POWERK_TOKEN` فارغًا. اضبط
   `POWERK_ARGS=--secure-cookies`. التسجيل مفتوح افتراضيًا؛ أضف
   `--no-open-registration` عندما تريد إغلاقه. اترك `POWERK_FCM_SERVICE_ACCOUNT`
   فارغًا ما لم تثبّت بيانات Firebase كما في الدليل.
3. جهّز `certs/` و`backups/` والجدار الناري كما في الدليل، ثم تحقّق وشغّل:

   ```sh
   sudo docker compose build --pull powerk
   sudo docker compose pull caddy backup
   sudo docker compose config --quiet
   sudo docker compose run --rm --no-deps caddy caddy validate \
     --config /etc/caddy/Caddyfile --adapter caddyfile
   sudo docker compose up -d
   sudo docker compose ps
   sudo docker compose logs --tail=100 powerk caddy backup
   ```

4. افتح عنوان HTTPS الخاص بك، وأنشئ حسابًا، ثم هيّئ المشترك واربط ملكيته كما يلي.

تقييد الوصول من Cloudflare يخص منفذ HTTPS **443** على الخادم؛ يجب أن يظل TCP **10086**
متاحًا للمشترك. منفذ HTTP الخلفي **8080** خاص وغير منشور. تأخذ حاوية النسخ الاحتياطي نسخة
عند بدء التشغيل وكل 24 ساعة، وتحتفظ بآخر 14 نسخة مكتملة. احتفظ بنسخ خارج الخادم أيضًا.
للتثبيتات القديمة، اتبع خطوات الانتقال في الدليل وترحيل الملكية أدناه قبل إيقاف الخدمة القديمة نهائيًا.

## التطوير المحلي

من مجلد المشروع:

```sh
cd server
python -m venv .venv
# Unix: source .venv/bin/activate
# PowerShell: .\.venv\Scripts\Activate.ps1
python -m pip install -e ".[test]"
python -m pytest tests -q
# اختبارات اختيارية لواجهة الويب؛ تحتاج Node.js، دون حزم npm:
node --test tests/
python -m powerk serve --data ./data
```

افتح `http://localhost:8080`، أو `http://<LAN-IP>:8080` من هاتفك، وأنشئ حسابًا.
الحساب مطلوب حتى بدون `--token`. اتصال HTTP المحلي غير مشفّر؛ خيار secure cookies
مغلق افتراضيًا لهذه البيئة. اسمح بمنفذي TCP 8080 و10086 في الجدار الناري للشبكة المحلية،
وامنع نوم الخادم، وثبّت عنوانه أو احجزه في DHCP. شغّل عملية خادم واحدة؛ اتصالات المشترك
والتحديثات اللحظية محفوظة داخل تلك العملية.

## تهيئة المشترك

1. شغّل الخادم وسجّل IPv4 المحلي أو العام للـVPS. نزّل أداة التهيئة **قبل** الاتصال
   بشبكة إعداد المشترك إن كنت تستخدم جهازًا آخر.
2. اضغط مطولًا على الزر الرئيسي نحو 10 ثوانٍ حتى يومض الضوء بسرعة.
3. اتصل بشبكة `TONLY_TAP_XXXXXXX` وكلمة مرور `LGU_XXXXXXX`، بنفس الحروف السبعة.
   عدم وجود إنترنت على هذه الشبكة طبيعي.
4. من مجلد المشروع، نفّذ:

   ```sh
   python tools/provision.py --ip <SERVER-IP> --ssid "YOURWIFI" --password "YOURWIFIPW"
   ```

   الرد المتوقع هو `up:ip:ip_ok` ثم `up:connect:connect_ok`. يمكن إضافة الكلمة
   الاختيارية `provision` قبل الخيارات. يجب أن يكون `--ip` عنوان IPv4، وليس دومين HTTPS؛
   اسم الواي فاي وكلمة مروره لا يقبلان `:` أو سطرًا جديدًا.
5. عُد إلى شبكتك العادية. يتصل المشترك بـ`<SERVER-IP>:10086`. راقب سجل الخادم ثم اربط
   ملكيته؛ المشتركات غير المرتبطة لا تظهر في قوائم الحسابات.

يحفظ المشترك عنوان خادم واحدًا. أعد التهيئة عند تغيير ذلك العنوان أو بيانات الواي فاي فقط.
الملف المُنزّل من `/powerk.py` هو أداة التهيئة، بينما `powerk.py` في جذر المستودع هو خادم
الرجوع القديم. تجاهل تلميحات الأداة القديمة لتشغيل `python powerk.py`؛ شغّل
`python -m powerk serve` من `server/` أو استخدم Compose.

### إذا كان الخادم بلا واي فاي

الجهاز الذي يُجري التهيئة فقط هو الذي يحتاج واي فاي واتصالًا بـ`192.168.1.1:30300`.

| الخيار | الخطوات |
|---|---|
| هاتف أندرويد مع Termux | على الشبكة العادية ثبّت Python بالأمر `pkg install python`، ونزّل `https://<YOUR-HOST>/powerk.py`. اتصل بشبكة الإعداد ثم نفّذ `python powerk.py --ip <SERVER-IP> --ssid "YOURWIFI" --password "YOURWIFIPW"`. |
| أي تطبيق TCP client | اتصل بشبكة الإعداد، وأرسل السطرين أدناه إلى `192.168.1.1:30300`، كل سطر في اتصال مستقل وبنهاية CRLF. |
| محوّل USB Wi-Fi | وصّله بكمبيوتر واتبع خطوات التهيئة السابقة. |
| لابتوب مستعار | انسخ `tools/provision.py` أو نزّل `/powerk.py`؛ استخدم IP **الخادم** وليس اللابتوب. |

```text
up:ip:<SERVER-IP>               -> up:ip:ip_ok
up:connect:<SSID>:<PASSWORD>    -> up:connect:connect_ok
```

## أول حساب وربط الملكية والمشاركة

1. أنشئ حسابًا برقم هاتف وكلمة مرور من 10 إلى 128 حرفًا. تُحوّل الأرقام المصرية
   `01XXXXXXXXX` إلى `+201XXXXXXXXX`؛ الأرقام الدولية تبدأ بـ`+`. تُرفض الكلمات الشائعة
   ورقم الهاتف نفسه. **لا تُرسل رسالة SMS أو OTP**؛ الرقم اسم مستخدم وليس إثبات هوية.
2. اختر **إضافة مشترك** وأدخل كود الإعداد المكوّن من سبع خانات سداسية عشرية، وهو الجزء
   الأخير من `TONLY_TAP_XXXXXXX`. يجب أن يكون المشترك متصلًا وغير مملوك لحساب آخر.
3. اضغط أي زر فعلي على المشترك خلال **60 ثانية**. **الضغط يغيّر حالة مخرج**؛ اختر حملًا
   آمنًا وأعده لحالته عند الحاجة. أوامر API العادية لا تُكمل ربط الملكية.
4. بصفتك المالك، افتح **الأشخاص** وشارك برقم هاتف مستخدم مسجّل، بدور `control` أو
   `viewer`. يجب أن يسجّل المستلم أولًا؛ المشاركة مع رقم غير مسجّل لا تنشئ دعوة أو وصولًا لاحقًا.

| الإجراء | owner — المالك | control — تحكّم | viewer — مشاهدة |
|---|:---:|:---:|:---:|
| قراءة الحالة والقواعد والطاقة والأحداث وإعدادات المشترك | نعم | نعم | نعم |
| تشغيل المخارج وتسميتها وإنشاء/تعديل/حذف القواعد | نعم | نعم | لا |
| ضبط عملة المشترك والسعر والميزانية وحدود التنبيه | نعم | لا | لا |
| عرض/إدارة الأعضاء ونقل الملكية وفك الربط | نعم | لا | لا |
| ضبط قنوات الإشعار والتفضيلات الشخصية | نعم | نعم | نعم |
| مغادرة مشترك تمت مشاركته | لا | نعم | نعم |

نقل الملكية يتطلب عضوًا موجودًا؛ يتحول المالك السابق إلى `control`. فك الربط يلغي وصول
الجميع ويعيد ضبط إعدادات المشترك وتفضيلات التنبيه، لكنه يحتفظ بالأسماء والقواعد والسجل.
تُراجع الصلاحيات مع كل طلب وكل رسالة WebSocket صادرة.

### التثبيتات القديمة

أنشئ حساب المالك المطلوب باستخدام البيانات القديمة أولًا. انسخ `powerk.json` و`powerk.db`
احتياطيًا، وأوقف الخادم، ثم نفّذ من `server/`:

```sh
python -m powerk migrate --data /path/to/existing/data --owner +201001234567
```

يربط هذا الترحيل المشتركَات الموجودة بالحساب مرة واحدة، وينسخ الإعدادات العامة للمشتركات
وقنوات إشعار المالك، ويحافظ على الأسماء والقواعد والسجل. في Compose، أوقف `powerk`
واستخدم وحدة بياناته مع استبدال أمر الدخول:

```sh
sudo docker compose stop powerk
sudo docker compose run --rm --no-deps --entrypoint python powerk \
  -m powerk migrate --data /data --owner +201001234567
sudo docker compose up -d powerk
```

لا تشغّل الخادمين القديم والجديد على البيانات نفسها في الوقت نفسه. راجع
[server/README.md](server/README.md) لتفاصيل علامات الترحيل والرجوع.

## الأتمتة والطاقة والإشعارات

| الميزة | السلوك |
|---|---|
| جدول | تشغيل أو إيقاف مخارج محددة في وقت محلي وأيام محددة |
| مؤقّت | تنفيذ مرة واحدة بعد مدة؛ ينتظر حتى خمس دقائق إن كان المشترك غير متصل |
| دورة | تكرار مدد التشغيل والإيقاف |
| إيقاف تلقائي | إيقاف المخرج بعد بقاء قدرته أقل من حد معيّن لمدة محددة |
| الطاقة | سجل يوم/أسبوع/شهر/سنة وتكلفة تقديرية بسعر ثابت لكل مشترك |
| الميزانية | تنبيهات لكل مشترك عند 50% و75% و90% و100% |
| التنبيهات | انقطاع الاتصال بعد 60 ثانية، وعودته، وحدود الحرارة/القدرة، ونشاط القواعد |

تستخدم القواعد **المنطقة الزمنية للخادم**، وهي `Africa/Cairo` في Compose. الموعد الذي يفوت
والمشترك غير متصل يُسجّل ولا يُنفّذ لاحقًا. قراءات الطاقة تقديرية وليست فاتورة. أول قراءة بعد
بدء الخادم هي خط الأساس؛ استهلاك فترة توقف الخادم لا يُستعاد. إذا انقطع المشترك ثم عاد والخادم
ما زال يعمل، يمكن احتساب فترة الانقطاع من فرق العداد المحفوظ.

يضبط كل مستخدم قنواته الشخصية عبر **ntfy** و/أو **Telegram** وتفضيلات أحداث كل مشترك،
ثم يستخدم **إرسال تجربة**. إشعارات التحذير والتنبيه مفعّلة افتراضيًا، والأحداث المعلوماتية
معطّلة. يدعم الخادم أيضًا **FCM** اختياريًا بحساب خدمة Firebase وتوكنات أجهزة مسجّلة.
يسجّل تطبيق أندرويد الجهاز بعد تسجيل الدخول ويحذفه عند الخروج.

## الأمان

- تُجزّأ كلمات المرور باستخدام Argon2id. توكن الوصول صالح 15 دقيقة؛ يتغيّر توكن التجديد
  عند استخدامه ويظل صالحًا 30 يومًا من إصداره. عند ضياع رد التجديد، تُسمح بمحاولة واحدة
  خلال **مهلة 60 ثانية**، بشرط عدم استخدام توكن التجديد الناتج عن المحاولة الأصلية.
- يستخدم الويب ملفات ارتباط HttpOnly وحماية CSRF؛ فعّل secure cookies خلف HTTPS.
  يمكن للمستخدم تغيير كلمة المرور وإلغاء الجلسات.
- توجد حدود لمحاولات الدخول والتسجيل والتجديد والربط والمشاركة وطلبات API وWebSocket.
  التزم برد `429` ومدة `Retry-After`.
- واجهة الويب لها سياسة CSP صارمة، مع معالجة آمنة للنصوص واختبارات لمنع رجوع ثغرات XSS.
  سجل الأمان الشخصي متاح عبر `/api/me/security-log`.
- يستخدم Caddy شهادة Cloudflare Origin CA وAuthenticated Origin Pulls. يقصر الجدار
  الناري HTTPS على Cloudflare، وتحدد إعدادات trusted proxy مصادر ترويسات IP الموثوقة.
- بروتوكول TCP للمشترك **غير مشفّر ولا يوثّق الجهاز تشفيريًا**. الربط بزر فعلي وقائمة MAC
  الاختيارية لا يغيّران هذا القيد.
- الخيار القديم `--token` يمنح وصولًا كاملًا للمشتركات ويتجاوز الأدوار. اتركه غير مضبوط
  لتشغيل الحسابات فقط. تنزيلات الواجهة وأداة التهيئة وAPK عامة ولا تكشف بيانات الحسابات.

## تطبيق أندرويد

يدعم التطبيق الحسابات والربط بزر فعلي والأدوار والمشاركة ونقل الملكية وإعدادات كل مشترك
والإشعارات الشخصية والقواعد والطاقة والتنبيهات. يشمل العربية والإنجليزية وثلاثة مظاهر،
وويدجت للمخرج والمشترك والاستهلاك، وزرًا في الإعدادات السريعة. دور المشاهدة لا يسمح بالتحكم.

اضبط الخادم في التطبيق على عنوان HTTPS لخادمك. لتغيير العنوان الافتراضي، ضع
`powerk.serverUrl=https://your.domain` في `android/local.properties` قبل البناء.
يُقبل HTTP المحلي لعناوين IP الخاصة وloopback وأسماء `.local`. تُحفظ توكنات الوصول والتجديد
مشفّرة بمفتاح من Android Keystore. يتشارك التطبيق والويدجت وزر الإعدادات السريعة معالجة
التجديد. أثناء ظهور التطبيق يبقى اتصال WebSocket مفتوحًا (مع استعلام احتياطي كل 60 ثانية،
وكل ثانيتين عند انقطاع الاتصال)، ويستقبل إشعارات FCM. البناء بدون
`android/app/google-services.json` يعطّل الإشعارات.

ابنِ التطبيق باستخدام JDK 17+ وAndroid SDK:

```sh
cd android
./gradlew :app:assembleRelease
# Windows: .\gradlew.bat :app:assembleRelease
adb install -r app/build/outputs/apk/release/app-release.apk
```

تستخدم نسخة release أداة R8 وتقليص الموارد. عند غياب `keystore.properties` يُستخدم توقيع
التطوير؛ راجع [PERFORMANCE.md](android/PERFORMANCE.md) لإعداد التوقيع. يقدّم `/powerk.apk`
الملف المحدد بخيار `--apk`، أو نسخة debug افتراضيًا إن كانت موجودة. في Compose، ضع نسخة
release في `deploy/apk/powerk.apk` وأضف `--apk /apk/powerk.apk` إلى `POWERK_ARGS`.

## واجهة الويب وAPI

تضم الواجهة المخارج والقواعد والطاقة والتنبيهات والإعدادات، مع شاشات الحساب والمشاركة.
تدعم العربية من اليمين لليسار والإنجليزية وثلاثة مظاهر وخطوطًا مضمّنة دون موارد صفحة خارجية.
ملفات HTML وJavaScript وCSS موجودة في `server/powerk/web/`.

راجع [API.md](API.md) لتوكنات Bearer وملفات الارتباط وCSRF والصلاحيات وأوامر HTTP ورسائل
WebSocket وتسجيل الإشعارات والتعامل مع الأخطاء. يعرض `/api/debug` بيانات التشخيص الخام
للمشتركات المتاحة للحساب فقط.

## مرجع البروتوكول

صيغة الرسائل التي يتحدثها المشترك على TCP 10086 :

| الاتجاه | الرسالة |
|---|---|
| من المشترك إلى الخادم | `up:bootinfo:<model>;<mac>;<mac>;<fw>;connect` |
| من المشترك إلى الخادم | `up:getinfo:<ch>:<runtime>;<relay on/off>;<state>;<overload>;<overheat>;<power mW>;<energy hex Wh>;<prev hex>;<config hex>;<status>;<event hex>;<temp C>` ×4 |
| من المشترك إلى الخادم | `up:power_report:<ch>:<mV>` (≥50000) أو `:<mA>` |
| من المشترك إلى الخادم | `up:query:<rssi>` |
| من المشترك إلى الخادم | `up:event:onoff:<0-4>:on\|off` (الزر الفيزيائي، و `0` = الكل) |
| من الخادم إلى المشترك | `up:getinfo:all`، `up:onoff:<1-4>:on\|off`، `up:power_report:1:vol`، `up:query:wifirssi` |
| نقطة الإعداد `192.168.1.1:30300` | `up:ip:<ip>` ← `up:ip:ip_ok`، و `up:connect:<ssid>:<pw>` ← `up:connect:connect_ok` |

لا يوجد أمر `up:onoff:0`؛ "الكل" يُرسل كحلقة على المقابس 1 إلى 4. بعض الرسائل تأتي
مبطّنة ببايتات NUL، والمنفذ ثابت على 10086.

## حل المشكلات

| العَرَض | الفحص / الحل |
|---|---|
| `Not reachable` أثناء التهيئة | اتصل بـ`TONLY_TAP_*`، وأعد وضع الإعداد، وتحقّق من الوصول إلى `192.168.1.1:30300`. |
| الحساب لا يعرض مشتركات | التهيئة غير ربط الملكية. اربط مشتركًا متصلًا وغير مملوك، أو اطلب من مالكه مشاركته مع رقمك المسجّل. البيانات القديمة تحتاج `migrate --owner`. |
| الربط يفشل أو تنتهي مهلته | راجع الكود السداسي ذي الخانات السبع وTCP 10086 والملكية، واضغط زرًا فعليًا خلال 60 ثانية. |
| المشترك غير متصل | راجع واي فاي 2.4 غيغاهرتز وIPv4 الثابت والجدار الناري لـTCP 10086 وسجل `docker compose logs powerk`؛ شغّل خادمًا واحدًا. |
| HTTPS لا يعمل والمشترك متصل | راجع DNS وproxy في Cloudflare وشهادات Origin CA/AOP وسجل Caddy ونطاقات الجدار الناري. الوصول المباشر إلى HTTPS على الخادم محجوب عمدًا. |
| `401` أو تكرار طلب الدخول | سجّل الدخول مجددًا إن فشل التجديد، وتحقّق من إلغاء الجلسات وعنوان الخادم. فعّل `--secure-cookies` خلف HTTPS. |
| `403` عند تعديل شيء | راجع الدور، وحماية CSRF للطلبات بملفات ارتباط المتصفح. المشاهد لا يتحكم؛ المالك وحده يغيّر إعدادات المشترك. |
| `429` | انتظر مدة `Retry-After`؛ تجنّب تكرار الدخول/الربط أو تشغيل استعلامات دورية متكررة. |
| توقف التحديث اللحظي في المتصفح | يفترض أن يعود الاستعلام الدوري؛ راجع ترقية WebSocket وsecure cookies عبر الوكيل. تطبيق أندرويد يستعلم دوريًا حاليًا. |
| الجدول يعمل في وقت خاطئ | راجع المنطقة الزمنية للخادم/الحاوية، لا ساعة الهاتف. |
| لا تصل الإشعارات | راجع قنواتك وتفضيلات المشترك ثم إرسال تجربة. تنبيهات أندرويد الحالية تصل عبر ntfy/Telegram. |
| تنزيل APK يعيد `404` | ابنِ APK واضبط `--apk`؛ صورة Docker لا تحتوي على نسخة أندرويد مبنية. |

## ما لا يفعله المشروع

- كيانات MQTT/Home Assistant أو Matter أو تحديث الفيرموير OTA.
- التحقق برسائل SMS أو استرجاع كلمة المرور عبر الهاتف.
- شرائح التعريفة والضرائب أو قياس طاقة يصلح للفوترة؛ السعر ثابت لكل مشترك.
- تشفير بروتوكول المشترك الأصلي أو توثيق الجهاز تشفيريًا.
- تنفيذ قواعد الخادم أثناء توقفه.
